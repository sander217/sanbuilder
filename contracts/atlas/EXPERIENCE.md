# Atlas Web Experience Contract

Atlas is fictional starter data. Replace this contract before a real delivery run.

## Work library

Users can understand the collection state, create their first item from an empty state, and return to recent work. Empty, loading, populated, error, and recovery states must be designed together.

## Guided task

Users can state an outcome, inspect what automation proposes, approve consequential actions, follow progress, stop safely, and recover unfinished work. Approval describes scope and consequence before execution.

## Responsive behavior

Information hierarchy and task continuity must survive desktop, tablet, and mobile layouts. Responsive work may change composition but not hide required decisions or recovery controls.
